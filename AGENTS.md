## Classification contract

- Read data/input/RAW_INCIDENTS.csv directly with configured headers, nonblank unique configured ID values, and consistent CSV rows. Require definitions for included incident fields and all configured input roles. Reject exclude names absent from the actual CSV and exclusions leaving no incident-data columns. Prevent input/output-name collisions. Preserve source headers and values without renaming or cleaning.
- Use Pydantic and strict Structured Outputs; keep the configured ID column (default INCIDENT_ID) local. Send task/rules as system instructions and incident JSON as user-message data.
- Preserve every source value in output. Send only included incident fields, ordered by input_order then remaining source order. The default order is narrative, causes, closure/resolution, investigation history, supplier/product context, then metadata. Assess support, counterevidence, confirmations, and corrections across included fields. Order, names, or recency alone do not establish authority. Return concise rationales, not internal chain-of-thought output.
- Preserve all 20 output roles and the [response order](docs/llm.md#classification-response) across rendered prompt, Pydantic, and CSV. Actual names come from columns.yml output; llm_ names are defaults. Source columns come first. Order is an organizing aid, not a correctness guarantee.
- Accountability is HSBC, SUPPLIER, or UNCERTAIN. UNCERTAIN is successful unresolved attribution; explain its limits in the accountability rationale. The 20 fields group into Classification (seven), Supplier (five), Incident context (six), and evidence (two).
- Keep three separate textual ratings. Attribution evidence is UNSUPPORTED/WEAK/MODERATE/STRONG/VERY_STRONG; reject UNSUPPORTED for HSBC/SUPPLIER and STRONG/VERY_STRONG for UNCERTAIN without repair. Confidence is VERY_LOW/LOW/MODERATE/HIGH/VERY_HIGH; UNCERTAIN with VERY_HIGH is valid. Reject numeric ratings and unknown labels.
- Source consistency is CONSISTENT, INCONSISTENT, or null. Unresolved material causal contradictions mean INCONSISTENT; minor or explicitly resolved discrepancies may be CONSISTENT. Use null for insufficient comparable material; absent/repeated accounts do not establish agreement. Ratings are not summed, calibrated probabilities, guarantees, or approval gates.
- All five Supplier fields are null for HSBC/UNCERTAIN. For SUPPLIER, missing name, product/service, or action/failure becomes Unknown; absent extra information stays null. Use the documented base name without inventing a parent company. The nullable supplier-name rationale explains its source basis or Unknown; preserve useful entity/country detail in supplier additional information.
- Context fields extract recorded facts for any class; absent, ambiguous, or conflicting facts stay null. Incident country describes the affected incident/service, never inferred from headquarters, names, currency, or unrelated locations. Use unambiguous English country names, with semicolons for multiple countries. Affected/resolving actors are not automatically responsible. Restoration describes an actual action or workaround; impact quantities require source support.
- The HSBC function uses BUSINESS/TECHNOLOGY/MIXED/UNCERTAIN; the schema also permits null for HSBC and clears it for other classes. It describes accountability, not the cause type or affected service. Keep causing-party, supplier-country, supplier-accountability, and supplier-causal-explanation outputs outside the schema; add no information-sufficiency or supplier-name score.
- Evidence columns is a string list accepting []; preserve order and join with comma and space in one cell. Check structure only, without individual-name/duplicate/blank/count validation.
- Citations is a string list accepting [], saved with Classification: line prefixes. Check structure only, without quote/source/duplicate/blank/length validation.
- Preserve completion/refusal/schema validation and Azure-compatible schema restrictions. The provider schema is flat with all 20 required keys, nullable where declared. Keep class-conditional rules in the prompt and local Pydantic validator; do not claim provider enforcement through unsupported if/then/else schema keywords. Requests use existing provider defaults without temperature or token controls.
